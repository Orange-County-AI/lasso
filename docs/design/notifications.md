# Notifications (`src/notify.go`, `src/webpush.go`, `src/notifywatch.go`, `src/notifycli.go`, `src/web/public/sw.js`, `src/web/src/lib/push.ts`)

An agent that blocks — a tool approval, omp's plan gate, codex's "Action Required" — stops until a human answers, and nothing in lasso could tell that human unless they were already looking at a screen. `notice`/`notifyUI` is an SSE toast, so it reaches open tabs only. This reaches a locked phone.

The split is deliberately two registries, so the second of either costs nothing: a **kind** says what happened (`notifAgentBlocked`, inferred by the watcher; `notifAgentMessage`, an agent deliberately pinging its human; `notifTest` for the Settings button), a **transport** says how it reaches a human (`webPushChannel` today). Nothing above the transport knows what Web Push is — a `notification` carries text, a collapse tag, and the host the event happened on, never endpoints or keys.

Two delivery forms, because the callers differ in what they can wait for: `publishNotification` is fire-and-forget for the poll loop, `deliverNotification`/`notifyNow` are synchronous and report what took it. An agent that pings its human MUST get that answer — "sent" when nothing is subscribed is the one reply that would make the feature worse than not having it — so both the `notify` tool and the Settings test button go through `notifyNow`, and `lasso notify` exits non-zero on `sent:false`.

- **Web Push, standard library only** (`webpush.go`). RFC 8291's derivation over RFC 8188's `aes128gcm` framing, with an RFC 8292 (VAPID) ES256 JWT; `crypto/ecdh`, `crypto/hkdf` and `ecdsa.ParseRawPrivateKey`/`PublicKey.Bytes` cover all of it since Go 1.24, so there is no dependency to audit. `sealWebPush` takes the salt and the ephemeral key as parameters purely so the RFC 8291 §5 test vector reproduces byte for byte (`webpush_test.go`) — that vector is the only way to prove the derivation without a phone.
- **The VAPID `sub` claim is the subscription's page origin**, and that is not cosmetic: Apple answers **403 BadJwtToken** for anything that is not a `mailto:` or a full https URL, which is exactly what the `mailto:lasso@<hostname>` a self-hosted server would otherwise invent looks like. Verified against the live `web.push.apple.com`: an origin-derived subject gets through to a `BadWebPushToken` (i.e. the JWT and the encrypted body were accepted, only the fabricated device id was not), while the hostname fallback is refused outright. `LASSO_PUSH_CONTACT` overrides; the fallback is only reachable for a non-https (loopback dev) origin, which is never Apple's service.
- **The VAPID keypair is generated once into `settings.push_vapid_private`** and must then never change: the browser pins the public key into every subscription it creates, so a new key silently invalidates every registered device. It is stored usable (not hashed) because it has to sign unattended — the same trust model as the OAuth client secret already in that db.
- **404/410 is the only failure that deletes a device.** That is RFC 8030's "this subscription no longer exists". A 403 (our credentials) or a 5xx (their service) is recorded on the row and retried — pruning on those would delete healthy devices over a transient outage, and the Settings list shows `last_error` precisely so a device that stopped working says so instead of looking identical to one that works.
- **The watcher polls, and only when something is listening** (`notifywatch.go`). It reuses `panesSnapshot`, not its own enumeration: that aggregation already has per-host deadlines, already degrades to last-good panes, already resolves the status lasso considers authoritative (herdr's, corrected by title reads and the omp plan gate), and its 1.5s cache makes a poll that lands near a browser's ⌘K refresh free. `notifyEnabled()` is checked first, so with no device subscribed the whole feature costs one `COUNT(*)` against a local sqlite file every 10s and touches no host.
- **Detection is a transition into `blocked`**, per pane, with a 5-minute floor per pane (`notifyRenotify`) so an agent that answers one approval only to raise the next buzzes once. A pane's remembered status outlives its disappearance by `notifyForget` (10m), so an unreachable host coming back is not read as every one of its agents having just blocked. Deliberately **no first-poll baseline**: an agent that blocked while lasso was restarting, or while notifications were being switched on, would otherwise never be announced at all — which is the hole this exists to close.
- **A pane is keyed by host + pane id** (`notifyPaneIdentities`), since pane ids are unique only within a host. That keying is also what makes the aggregation's last-good fallback inert: a stale listing re-states keys the watcher already recorded instead of reading as new.
- **The notification names a host, never a pane.** Opening it lands the tab on the right machine and stops there, because herdr's focus is one global per session shared with the TUI and every other client — a link that focused a pane would move it for everyone (the same reason `lib/url.ts` keeps focus out of the URL).
- **Everything the service worker needs is in the encrypted payload.** `sw.js` runs with no page and cannot call back into lasso: behind Cloudflare Access an unauthenticated fetch returns a login page. So a payload carrying only an id would be a notification the phone cannot render.
- **The service worker caches nothing and has no `fetch` handler.** lasso is a live view of machines you are driving, so an offline shell of it would be a lie, and a stale bundle in front of a self-updating binary is a support burden with no upside. That absence is also what makes `skipWaiting`+`clients.claim` safe. `/sw.js` is served `no-cache, must-revalidate` (`noStore` in main.go) because it is the one asset whose URL never changes — Cloudflare would otherwise hold an edge copy of it for hours past an update.
- **iOS gates push behind installation**, so `lib/push.ts` reports `needs-home-screen` distinctly from `unsupported` and the Settings section says which. `enablePush` must run straight from the click: Safari only honors `Notification.requestPermission` from a user gesture. A subscription pinned to a *different* server key (a restored db, another lasso) is dropped and re-minted rather than left to throw `InvalidStateError`. Verified end to end in Chrome via CDP `ServiceWorker.deliverPushMessage`: the worker raises the notification, a repeated tag replaces rather than stacks, and an unparseable payload still shows something (a `userVisibleOnly` subscription that shows nothing loses its permission).
- **`lasso notify` is a CLIENT of the `notify` MCP tool** (`notifycli.go`), not a second implementation: one description the model reads, one rule about attribution, one place where "sent" is decided. It was the first CLI subcommand to speak MCP and `lasso mcp` generalized it (they share `dialMCP`); `closeme` deliberately POSTs a plain endpoint instead, because the two commands are different things: closeme is lasso acting on its own agent record, while notify is an agent using a tool, and giving the CLI its own `/api` route is how the two would drift. `LASSO_URL`/`LASSO_LISTEN` locate the server, and it sends `LASSO_MCP_TOKEN` or the `UI_AUTH` basic credentials when either is set (both usually absent, since `/mcp` is open by default).
- **`notify` attributes through `resolveCallerAgent`** — extracted from `whoamiTool` so the sender's name is exactly the answer whoami would give, rather than a second, subtly different resolution. A lock-screen notification is read title-first, so the agent's workspace label ("Port the auth tests") is the title and the message is the body. An unresolvable pane is NOT an error: the message still matters, so it goes out titled "lasso" with the resolution problem in `detail`.
- **A deliberate message carries no tag, so nothing collapses.** The watcher tags per pane on purpose (repeated "still blocked" is one entry); two messages an agent chose to send are two things it said, and folding them would hide the first. That is also why `sw.js` must leave an absent tag absent instead of defaulting to a shared constant — the bug that default would cause is silent.
