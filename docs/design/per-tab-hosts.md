# Per-tab hosts (`src/reqhost.go`, `src/hostfeed.go`, `src/switch.go`, `src/web/src/lib/host.ts`)

Which host lasso drives is a property of the **browser tab**, not of the process. Two tabs sit on two machines at once; neither disturbs the other.

It used to be one global pointer (`active.b`) that `POST /api/host` swapped, so a switch in one tab moved every other tab's terminal, pane list and file viewer. That pointer survives as the **default host** — the one lasso booted on (`local`, or `-host`) — which answers for any caller naming none: a fresh tab before it chooses, MCP `list_hosts`' `active`, background jobs. It is immutable at runtime.

- **A tab announces itself on every request.** Two carriers, because one cannot cover both call shapes: `fetch` sends the `X-Lasso-Host` header (`hostFetch` wraps every call in `lib/api.ts`), while an `EventSource` and an `<iframe>` src can only carry `?host=`. `requestHost` prefers the query param, so a hand-typed or deep-linked URL is not overridden by the page's own wrapper. `reqBackend(r, explicit)` resolves the backend, with a request's own payload host (the sidebar's `host` field, which follows the FOCUSED pane) winning over the tab's.
- **The tab's choice lives in `sessionStorage`**, seeded from a `?host=` already in the page URL. sessionStorage is per tab by construction, so a new tab starts on the default host instead of inheriting wherever another one wandered, and it survives a reload. `moveTabToHost` attaches server-side, records the choice, then reconnects the SSE stream — in that order, since recording it early would address a host whose terminals are not up yet.
- **`POST /api/host` no longer switches anything.** It *attaches*: pools the host's connection, makes sure its two ttyds are resident, and reports the herdr version/protocol. It mutates no shared state, so two tabs attaching to two hosts is two independent no-ops on each other.
- **One feed per watched host** (`hostfeed.go`). Each runs its own `pane.list` poll, its own herdr event subscription, and its own `panes_rev`/`lastSig`, and pushes only to the tabs watching it. Started on first interest, stopped `feedIdle` (90s) after the last watcher leaves — the poll is herdr's most expensive method, so an unwatched host must cost nothing. **The default host is exempt** and polls for the life of the server, because it is what a fresh tab lands on. Cost is therefore per *watched host*, not per tab: three tabs on titan is still one poller. **What makes the stop real is that `run()` no longer touches `f.cancel`**: it marks itself with its own `running` flag (which is only there to tell a `repoint`'s `startSub` whether run() has taken over the subscription yet). Using "is cancel set" as that marker meant run() wrote `f.cancel = func(){}` over the feed context's real cancel, so `stopFeedIfIdle` logged `stopped watching <host> (idle)` and the poller and its event subscription ran on for the life of the process — paying `pane.list` forever for a host nobody was watching, and writing that host's process-global pane.list cache from a feed the hub had already forgotten. `TestStoppedFeedStopsPolling` pins it, with `-poll` set above `paneListTTL` so a zombie poller's ticks reach the backend instead of being absorbed by the cache.
- **Theme and UI-prefs revisions stay global**, on the hub, and are stamped into every feed's frames. They are properties of this lasso, not of a host; re-resolving `config.toml` once per watched host would multiply a file read and a fleet-wide theme sync by the number of open hosts.
- **Terminals route by host in the URL**: `/terminal/<slug>/` and `/shell/<slug>/`, each ttyd spawned with its own `-b` base path so its asset and websocket URLs land back on the same instance. The instances were always per host; only the role's `active` pointer had to go. `hostSlug` appends a digest when `sanitizeAlias` alters the alias — with per-host routing a collision means two hosts sharing one terminal, not merely an odd filename. **The reverse proxy's outbound URL host must stay unique per slug** (`<slug>.ttyd.invalid`): `http.Transport` pools keep-alive connections by it, and one shared placeholder served the second host's request down the first host's connection, whose ttyd answered 404.
- **"Is this the active host?" had exactly one answer**, so every guard built on it would now reap a second tab's host out from under it. `hostInUse` (default host, or watched, or holding a resident terminal) replaces it in `reapHostBackends`; `hostWatched` (default or watched, deliberately *not* counting terminals, which would make every terminal exempt from the reaping it decides) replaces it in the ttyd eviction and idle sweeps.
- **The `pane.list` cache is keyed by host**, each entry with its own mutex — sharing one would serve titan's panes under norm's name, and one host's herdr event would drop another's snapshot. Its 400ms TTL runs from when the snapshot was **taken**, not when it landed: the call costs 0.5–1.5s on a busy session, so timing the reply made a listing of the session as it was seconds ago read as fresh. For the same reason `invalidatePaneList` stamps a time **without** taking the entry's lock (which is held for the whole call) and `herdrPaneList` serves the cache only when its snapshot postdates that stamp — a caller coalescing onto an already-in-flight call is usually the one asking about something that has just appeared. `createAgent` invalidates too, so the browser's post-create pane lookup can see the pane it is about to focus.
- **`term_rev` is gone.** It existed to make the browser remount its iframes on a switch; a tab changing host now changes its own iframe `src`, which remounts it.
- **The terminal's palette comes from the DOCUMENT, not the process** (`withLiveTtydTheme` in `src/main.go`). `-t theme=` is read from argv once, so a resident ttyd keeps serving the palette it was spawned under — and nothing retires an instance on a re-theme (killing one drops an open terminal's websocket and its `/shell/` child with it). So the document request is redirected onto `?theme=<live ITheme>`: ttyd's frontend merges options as `{…built-ins, …server-sent, …URL query}`, re-applying the query on every reconnect. This is also what the programs *inside* see — xterm.js answers herdr's OSC 11 background query from the merged theme, which is how omp and opencode infer light vs dark in a pane. The app's own page hid the staleness (`lib/theme.ts` re-pins `window.term.options.theme` from `/api/theme` on every change, which is still what repaints an OPEN terminal); it only showed where nothing repaints from outside, i.e. a browser window opened directly on `/terminal/<slug>/` — which served a cream rose-pine-dawn canvas under dark herdr chrome for hours. Only the document is rewritten (assets, `/token` and the websocket pass through), the redirect is `no-store` (a cached one would pin the palette it was issued under), and a query already naming a theme is passed through so the redirect cannot loop.
