# The input dial (`src/web/src/lib/mobile-input-dial.ts`)

The floating control in the bottom-right of each terminal iframe — the root, its arc of targets, and the two satellite buttons it carries, `.dial-chat` above and `.dial-sidebar` below — is **the app's chrome wherever the footer is not**. It lives inside the ttyd document rather than in the parent, because `preventDefault` on a same-document pointer gesture is what keeps the iOS software keyboard up; a control in the parent would dismiss it and could not reopen it.

- **The sidebar earned its own button, and that cost the root the corner.** It was one target on the Lasso branch — a hold, a slide and a release past two neighbours for the panel a phone reads its files, its settings and now its agent list in. As a satellite it is one tap, in the same place at every level, and it mirrors the chat button exactly (same `left`, a `top` offset against the chat's `bottom`), which is what makes the two read as one column beside the root rather than two loose circles. There is no room for it where the dial sat: a 44px circle below the root needs ~42px of clearance plus its own radius, and the root's centre was only 47px above the inset. So the whole box lifts by `SAT_DROP` (41px) and the sidebar button lands on the 18px line the root used to hold. **`TERMINAL_BOTTOM_GAP` is deliberately unchanged**: the group grew upward only, so the lowest painted pixel is where it always was, and the rows the gap clears are the same rows. What it costs is the root leaving the thumb's home corner, which the sidebar button now occupies. Lasso's arc is two targets after the move (Search, Host), re-spaced onto the root arc's own r=220 and 29° spacing so a level change slides a target along one curve instead of onto a different one.
- **Two conditions mount it, and either alone is enough**: a coarse pointer (asked of the IFRAME) or a viewport below `md` (`(max-width: 767px)`, asked of the **PARENT**). The parent is not a detail: this document is only the terminal *column*, so a width query here measures the panel split — a wide window with a wide sidebar would read as narrow and grow a dial beside a footer that is still there. `watchDialConditions` ORs them and mounts exactly **once**, since a phone matches both and a dial per condition would be two dials in one document with one teardown.
- **The width half exists because a narrowed desktop used to have no chrome at all.** The footer is `md:flex`, so dragging a window under 768px takes New, the host menu, both sidebars, the shortcuts sheet and Chat off the screen — and with a mouse and no touchscreen nothing replaced them. The dial already works a pointer (a click opens the ring, a click on a target fires it; the CSS has carried `cursor: grab` and a hover state throughout), so the fix mounts the existing control rather than growing a second copy in the parent document.
- **Both conditions are WATCHED, never sampled at boot.** A hybrid folded into tablet mode, a keyboard case detached, a window dragged across the breakpoint — each flips one of them, and a sampled gate is wrong in one direction or the other for the rest of the page's life. The teardown drops the `#terminal-container` gap with the stylesheet, so a window widened back past `md` gets its bottom rows back.
