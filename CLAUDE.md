# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Lasso is a Go backend (`src/main.go` and friends) that serves a React/TypeScript SPA. All Go code lives under `src/` (the Go module root — `src/go.mod`). The frontend in `src/web/` is **built and embedded into the Go binary** — `go build` embeds `src/web/dist/`, so it must exist locally (run `mise run build`) but is **not** committed (it's gitignored). CI builds the frontend and produces release binaries.

## Commands

Backend (run from repo root, via [mise](https://mise.jdx.dev); Go sources are in `src/`):
- `mise run build` — builds the frontend (`bun run build` in `src/web/`) then `go build` in `src/` (binary → `./lasso`)
- `mise run dev` — Vite dev server with HMR, proxying to the Go backend (requires tailscale up; auto-bumps the dev port from 8190 if busy)
- `mise run test` — `go test .` in `src/`

Frontend (`src/web/`, package manager is **bun**):
- `bun run dev` / `bun run build` (`tsc -b && vite build`)
- `bun run typecheck` — `tsc --noEmit`
- `bun run lint` — `biome lint .`
- `bun run format` — `biome format --write .`
- `bun run check` — `biome check --write .` (format + lint fixes + import/class sorting)

## Frontend workflow

- Run `bun run typecheck` (`tsc -b` — the project references mean a bare `tsc --noEmit` checks *nothing*, since the root tsconfig has `files: []`) and `bun run lint` before considering frontend work done.
- `src/web/dist/` is the embedded bundle — gitignored and not committed. Run `mise run build` to regenerate it locally; CI builds it for releases.

## Formatting & linting

Tooling is **Biome** (`src/web/biome.json`) — it replaced Prettier + ESLint. Style: 2-space indent, no semicolons, double quotes, ES5 trailing commas, 80-col width. Tailwind class sorting is handled by Biome's `useSortedClasses` (aware of `cn`/`cva`). a11y rules are demoted to warnings (not previously enforced); don't treat them as blocking. Go code: standard `gofmt`.

## Security gotchas

- Never bind to `0.0.0.0`. Use loopback or the tailscale IP. For non-loopback access set `UI_AUTH=user:pass`.
- The file endpoints (`/api/file`, `/api/files`, and the write/rename/delete/upload trio) read and write arbitrary absolute paths as the running user — on the calling tab's host, or on any host lasso may drive when the request names one (`?host=` / a `host` field; see "File viewer host"). Safe only on a private tailnet.
- Running lasso nested inside herdr requires `allow_nested = true` in `~/.config/herdr/config.toml`.
- The `/mcp` MCP server is **unauthenticated by default** (exempt from `UI_AUTH` via `withAuthExcept`) — it lets any client that can reach lasso spawn and drive agents. Same trust model as `/api/file`: safe only on loopback / a private tailnet, or behind an edge auth gate (e.g. Cloudflare Access). It introduces no new binding. Set `MCP_OAUTH` (below) to gate it in the origin instead.
- **Unless `MCP_OAUTH` is set**, the origin deliberately implements **no** OAuth (no `.well-known`, no `401`/`WWW-Authenticate`). So OAuth-based MCP clients (Claude Desktop / claude.ai connectors) connecting to `/mcp` over the public hostname require **Managed OAuth enabled on the Cloudflare Access app** — Access then acts as the OAuth 2.1 authorization server (Dynamic Client Registration + auth-code/PKCE), runs the login against the existing Access policy, and issues tokens; the origin still sees an authenticated Access session and needs no auth code. Without it the client's registration fails ("Couldn't register with lasso's sign-in service"). This is an edge setting on the Access application, not a `cloudflared`/tunnel change. `oauth.go` keeps every OAuth route 404 while `MCP_OAUTH` is unset precisely so this Access path stays intact — don't make that metadata unconditional.

## MCP OAuth (`src/oauth.go`)

`MCP_OAUTH=client_id:client_secret` (environment only, like `UI_AUTH` — never argv) turns lasso into a small OAuth 2.1 authorization server for its own `/mcp` resource. Unset = today's open `/mcp`, unchanged.

- **Grants**: `client_credentials` (machine-to-machine — scripts, CLIs, Claude Code; restricted to the `MCP_OAUTH` client and to per-host clients minted with `lasso mcp-client add`, never to an open-DCR registration) and `authorization_code` + PKCE/S256 with `refresh_token` rotation. claude.ai / Claude Desktop custom connectors **cannot** use `client_credentials` — Anthropic's connector infra requires `authorization_code`+`refresh_token` and per-connection user consent — so their "Advanced settings → OAuth Client ID / Client Secret" fields are a *pre-registered client for the auth-code flow*. That's why both grants exist.
- **Routes**: `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`, `/oauth/register` (open DCR), `/oauth/token` — all exempt from `UI_AUTH`, since they're the credential-less half of the handshake. `/oauth/authorize` is **deliberately gated** by `UI_AUTH`/Access: that human gate is what makes open DCR safe (anyone may register; nobody gets a token without passing the door and clicking Approve).
- `/mcp` accepts **either** a bearer token **or** the `UI_AUTH` basic credentials, so the CLI and existing callers keep working without an OAuth dance.
- Redirect URIs: DCR clients get exact matching. The pre-registered client accepts any https/loopback callback (a connector's callback isn't known when the secret is minted) and the consent screen displays the exact target; set `MCP_OAUTH_REDIRECT_URIS=<comma-separated>` to lock it to an allowlist.
- Codes and tokens live in `oauth_*` tables in `lasso.db`, stored as SHA-256 hashes, so refresh tokens survive restarts and self-updates.

## Per-tab hosts (`src/reqhost.go`, `src/hostfeed.go`, `src/switch.go`, `src/web/src/lib/host.ts`)

Which host lasso drives is a property of the **browser tab**, not of the process. Two tabs sit on two machines at once; neither disturbs the other.

It used to be one global pointer (`active.b`) that `POST /api/host` swapped, so a switch in one tab moved every other tab's terminal, pane list and file viewer. That pointer survives as the **default host** — the one lasso booted on (`local`, or `-host`) — which answers for any caller naming none: a fresh tab before it chooses, MCP `list_hosts`' `active`, background jobs. It is immutable at runtime.

- **A tab announces itself on every request.** Two carriers, because one cannot cover both call shapes: `fetch` sends the `X-Lasso-Host` header (`hostFetch` wraps every call in `lib/api.ts`), while an `EventSource` and an `<iframe>` src can only carry `?host=`. `requestHost` prefers the query param, so a hand-typed or deep-linked URL is not overridden by the page's own wrapper. `reqBackend(r, explicit)` resolves the backend, with a request's own payload host (the sidebar's `host` field, which follows the FOCUSED pane) winning over the tab's.
- **The tab's choice lives in `sessionStorage`**, seeded from a `?host=` already in the page URL. sessionStorage is per tab by construction, so a new tab starts on the default host instead of inheriting wherever another one wandered, and it survives a reload. `moveTabToHost` attaches server-side, records the choice, then reconnects the SSE stream — in that order, since recording it early would address a host whose terminals are not up yet.
- **`POST /api/host` no longer switches anything.** It *attaches*: pools the host's connection, makes sure its two ttyds are resident, and reports the herdr version/protocol. It mutates no shared state, so two tabs attaching to two hosts is two independent no-ops on each other.
- **One feed per watched host** (`hostfeed.go`). Each runs its own `pane.list` poll, its own herdr event subscription, and its own `panes_rev`/`lastSig`, and pushes only to the tabs watching it. Started on first interest, stopped `feedIdle` (90s) after the last watcher leaves — the poll is herdr's most expensive method, so an unwatched host must cost nothing. **The default host is exempt** and polls for the life of the server, because it is what a fresh tab lands on. Cost is therefore per *watched host*, not per tab: three tabs on titan is still one poller.
- **Theme and UI-prefs revisions stay global**, on the hub, and are stamped into every feed's frames. They are properties of this lasso, not of a host; re-resolving `config.toml` once per watched host would multiply a file read and a fleet-wide theme sync by the number of open hosts.
- **Terminals route by host in the URL**: `/terminal/<slug>/` and `/shell/<slug>/`, each ttyd spawned with its own `-b` base path so its asset and websocket URLs land back on the same instance. The instances were always per host; only the role's `active` pointer had to go. `hostSlug` appends a digest when `sanitizeAlias` alters the alias — with per-host routing a collision means two hosts sharing one terminal, not merely an odd filename. **The reverse proxy's outbound URL host must stay unique per slug** (`<slug>.ttyd.invalid`): `http.Transport` pools keep-alive connections by it, and one shared placeholder served the second host's request down the first host's connection, whose ttyd answered 404.
- **"Is this the active host?" had exactly one answer**, so every guard built on it would now reap a second tab's host out from under it. `hostInUse` (default host, or watched, or holding a resident terminal) replaces it in `reapHostBackends`; `hostWatched` (default or watched, deliberately *not* counting terminals, which would make every terminal exempt from the reaping it decides) replaces it in the ttyd eviction and idle sweeps.
- **The `pane.list` cache is keyed by host**, each entry with its own mutex — sharing one would serve titan's panes under norm's name, and one host's herdr event would drop another's snapshot.
- **`term_rev` is gone.** It existed to make the browser remount its iframes on a switch; a tab changing host now changes its own iframe `src`, which remounts it.

## Agent visibility scope (`src/hostscope.go`, `src/callerscope.go`, `src/groups.go`, `src/mcpgroup.go`)

Two bounds decide which agents an MCP caller can see and message. Both apply. A third layer, groups, widens the second.

1. **What lasso can address** (`hostscope.go`) — the local box plus the concrete aliases in the ssh config lasso reads. Membership is the config's, never the agents db's, so a host whose alias was removed stops being listable/addressable instead of resolving to a target no call can reach. Reachability is deliberately *not* part of it: an alias whose box is asleep still resolves and gets an honest "unreachable" from the backend.
2. **What this caller may address** (`callerscope.go`) — per-credential. `lasso mcp-client add --host <alias>` mints one OAuth client per host; the resolved host rides `auth.TokenInfo` into every tool call, so a caller's host is derived from its token and cannot be asserted. Scope defaults to `self` (that host only); `--fleet` opts a trusted host up to the whole addressable set. `lasso mcp-client token <client_id>` mints a bearer token for clients that can only carry a header (`claude mcp add --header …`) — **no expiry by default**, since it sits unattended in a host's config where a rolling expiry is an outage on a timer; `--ttl 90d`/`2w`/`12h` for a dated one. Never-expiring tokens are stored with an empty `expires_at`, which `purgeExpiredOAuth` excludes explicitly (`''` sorts before every timestamp in SQLite) and `mcpTokenVerifier` translates into a synthetic future `Expiration`, because `auth.RequireBearerToken` rejects a zero one. Unidentified callers (no bearer token — open `/mcp`, or the `UI_AUTH` basic escape hatch) are fleet-scoped, which is the historical behavior.
3. **Groups** (`groups.go` resolution, `mcpgroup.go` CLI, `mcp_group*` tables) — the middle ground between `self` and `fleet`, purely **additive on top of `self`**: no new scope value, no `oauth_clients` change, `Fleet` still short-circuits first. Members are **hosts** (aliases or `local`), not credentials, so membership survives re-keying. Reach within a group's member closure is mutual; asymmetry comes from directed, **non-transitive** grants `A→B` (one hop). Nesting `@H` in `G` makes H's hosts mutual with all of `closure(G)` — grant, don't nest, if that is not the intent. `mcpTokenVerifier` resolves a self-scoped caller's reach **per request** into `TokenInfo.Extra["lasso.reach"]`, so group edits land on the next tool call with no re-mint and no session restart. Runbook and CLI: `docs/mcp-agent-scope.md`.

Consequences worth knowing:

- **Containment requires `MCP_OAUTH`.** With it unset, `withMCPAuth` is a no-op and every caller is unidentified, so provisioned per-host credentials — and the groups built on them — are inert; startup logs a warning saying exactly that.
- `host` now defaults to the **caller's own** host, not `local`. `local` means the box lasso runs on, which for a remote agent is someone else's machine; the old default silently pointed every remote caller at the lasso host's agents.
- `whoami`/`close_agent` keep "empty host = search every host I may reach" (`searchHost`, not `hostOr`), except that an identified caller collapses the search to its own host — which also retires the cross-host pane-id collision refusal. Groups reopen that only for `close_agent`, and only when the caller's reach spans more than its own host: `whoami` stays pinned to `cs.Host` (a caller's own pane is on its credential's host by definition). The empty-host `adoptPeerAgent` fallbacks are guarded by `cs.allows("local")`, or a group caller whose reach excludes local could close a local pane through them.
- MCP identity is **not** a sandbox. A fleet-scoped agent can proxy for a contained one, and a secret in a pod can be exfiltrated. If a trust zone is a real boundary, block the pod's network path to lasso and treat this as defense in depth.
- The spec offers nothing here: as of MCP 2025-11-25 `clientInfo` is a self-asserted name/version/title, no header identifies the caller, and the spec's own session-hijacking guidance is that the principal must be "derived from the user token and not provided by the client". Hence per-host credentials rather than a `host` argument or an `_meta` claim.

## Agent record reconciliation (`src/agentreap.go`)

The `agents` table is an append-only log; herdr's panes are not. Nothing used to compare them, so every agent whose pane was closed left a record that still read as live and "ready" — 139 records against herdr's 8 on titan — and each one was listed, unmessageable, and un-closeable (`pane_not_found` / `workspace_not_found`), with no route to clear it through the API.

`reconcileHostAgents(host, panes)` stamps `closed_at` on the records a successful pane enumeration contradicts. It is called from the two places that already hold a fresh per-host pane listing — `fetchAllPanes`' success branch (the `/api/all-panes` poll) and `listAgentsTool` (before it reads the records) — rather than from a timer of its own, which would have to re-enumerate every host to learn what those two already know.

- **Marked, not deleted.** The row is both "which agents are there" (where a dead one is noise) and the agent's history — the ⌘K switcher's "show closed" mode finds a finished session by work dir/prompt and reopens it. So `listAgents`/`listAllAgents` are **live-only**, `listAllAgentsIncludingClosed` serves `/api/agent-history`, and `findAgentRecordAny` serves reopen, which **revives** the record (`updateAgentPane` clears `closed_at`).
- The whole difficulty is that "no pane" has two causes and only one may condemn a record. Hence: only a **successful** enumeration reconciles (an unreachable herdr keeps returning a PARTIAL listing instead); **per host** always (ids and pane ids are unique only within a host); an **empty** pane list never condemns; records mid-boot are exempt for `agentBootGrace` (a boot holds a visible pane for all but its first instant, so the grace is sized against a lasso restart landing mid-create — unbounded, it stranded a "booting" record for three days); records with no `root_pane` are exempt; and a pane must be missing from **`agentReapMisses` consecutive** enumerations, which covers the last racy window (reopen re-pointing a record at a just-created workspace).
- **Foreign herdr sessions are untouched.** A pane lasso did not create (a long-lived bot like "Clem (OCAI)") has no record to tombstone and is derived from the pane listing on every call, so it comes and goes with the pane it is. A reconcile keyed on lasso's own records would silently drop them — a worse bug than the one being fixed.

## File viewer host (`src/panehost.go`, `src/agentcwd.go`)

The sidebar (Files tree, viewer/editor, Diff) follows the FOCUSED pane — its cwd *and* the host that cwd lives on. Those are two different questions once a pane is a window onto another box: `ssh <host> herdr agent attach <name>` (what a fleet attach script runs) and `herdr --remote <host>` both put a remote terminal inside a local pane, and every cwd herdr can report for it is the ssh client's — `/home/stephan` on titan for an agent working in `/home/dev/projects/norm` on norm. The viewer browsed the wrong machine outright.

`activeCwd` (agentcwd.go) now answers `(cwd, source, host)`, and asks about the hop first: `paneForeground` fetches `pane.process_info` once, `paneSSHHop` reads its foreground argv as an attach, and `remoteAttachCwd` asks THAT host's herdr where the attached pane is working (`agent.list` for a named agent, the focused pane of `pane.list` for a session-level attach), resolving the far side with the same precedence as a local pane — harness transcript over SFTP, then herdr's cwds. `Active.CwdHost` carries the answer to the browser as `cwd_host`, and `CwdSource` is prefixed `ssh:` when the far side answered.

- **Only a herdr ATTACH counts** — plus a herdr-mirror streamer, which is the same thing the plugin launches for you. A plain `ssh host` shell has no far-side pane to ask about — nothing on either end knows where it has cd'd to — so it keeps the local answer. Same for `herdr agent list` and friends: a one-shot remote command is not a window, and neither is `herdr-mirror daemon`/`status` (only its `pane` subcommand streams one). A false positive repoints the viewer (and its editor's saves) at another machine, so `hostAliasFor` also refuses any destination that isn't a host lasso may drive, and a named agent that is gone resolves to nothing rather than to some other pane. A mirror hop names a *pane id* rather than an agent, so `attachedPane` falls through to `paneByID`: a mirrored shell holds no agent, and its filesystem is still the one to show.
- **Every sidebar endpoint takes a host.** `/api/files`, `/api/file`, `/api/diff`, `/api/diff-file` (`?host=`), `/api/file-write`, `/api/file-delete`, `/api/file-rename` (a `host` body field) and `/api/file-upload` (a `host` form field) all resolve through `namedHostBackend`, and tilde-expand against THAT backend. The diff helpers take a `Backend` for the same reason — there is no active-backend `gitOut` any more. Half a cutover here means an editor saving to the wrong machine.
- **`namedHostBackend` short-circuits the DEFAULT host.** An empty selector, or one naming `defaultBackend().Name()`, resolves to that backend itself — the connection we already hold — rather than dialing the pool for the same box; anything else passes the `hostAllowed` gate (502 `host "x" not available`) and comes from the per-host pool, which holds exactly one connection per host shared by every tab on it. `setDefaultBackend` and `hostBackendFn` are the two seams handler and feed tests use to stand a fake fleet up without an ssh master (`diff_test.go`, `filehost_test.go`, `hostfeed_test.go`).
- **A host selector must not blur "no repo" into "no host".** `gitErrNoRepo` classifies the `rev-parse` failure: a plain directory answers 200 `isRepo:false`, while a transport failure stays 502. With `be` now resolved per request, that distinction carries the extra weight of telling a reachable host's non-repo directory from an unreachable host — collapsing them would report a broken remote as a clean tree.
- **The browsed host is UI state, not a live read.** `FilesTab` keeps `curHost` beside `curPath`: both track the focused pane while "follow" is on and freeze together the moment the user types a path or navigates. A host change re-roots even at an identical path (the per-directory caches are cleared first, so one host's listing is never shown for another's), and an open `FileViewer` keeps the host it was opened on — `FilesPanel` captures `{path, host}` together — so focus moving on doesn't redirect a save. `useDiff` keys on `cwd_host`, not the tab's host.
- **The tab's host is untouched.** This resolves where the pane's *work* is; the terminal, host switcher, and creator still follow `Active.Host`. Reading a remote pane's cwd must not move the tab onto that host.

## herdr-mirror awareness (`src/mirror.go`)

The [herdr-mirror](https://github.com/nikok6/herdr-mirror) plugin streams other machines' herdr workspaces into the local sidebar. Each mirrored remote workspace is a REAL LOCAL workspace (label `"<host>: <remote label>"`) and each mirrored pane a real local pane running `herdr-mirror pane <ssh-target> <remoteWs>:<remotePane>` — so a pane listing alone cannot tell someone else's agent from one of yours. On titan that is 32 of 61 panes across 9 hosts, which made ⌘K mostly a list of other machines' work that read as local.

`gridPane` therefore carries `MirrorHost` / `MirrorLabel` / `MirrorWorkspace` / `MirrorPane`; the ⌘K palette lists **this tab's host only** and groups its rows by the machine the work is actually on.

- **The signal is the daemon's own object map**, `~/.local/state/herdr-mirror/<host>-map.json` (remote id → local id, per host, plus the workspace's `lastRemoteLabel`). Not the label prefix — it is configurable per host (`prefix` in hosts.toml) and a local workspace may legally contain a colon. Not `pane.process_info` either: that is authoritative and carries the ssh target, but it is one RPC *per pane* on every `/api/grid` poll. The map also hands over the un-prefixed remote label and the remote ids for free, so nothing has to be parsed back out of a display string.
- **The sentinel cwd is a gate, never a classifier.** Every mirror pane reports `~/.local/state/herdr-mirror/.mirror-pane`, so `anyMirrorSentinel` decides in O(panes) whether reading the maps is worth it and a host running no mirrors pays nothing. It may not condemn a pane: a real local pane that cd'd in there reports the same path (verified on titan — the workspace herdr-mirror was installed from does exactly that).
- **Stale maps are inert.** An entry whose local workspace is gone (a retired host's file lingers) matches no pane; a pane the daemon has not written yet is simply unattributed until the next refresh, never attributed to the wrong host. One unparseable map does not take the other eight hosts down.
- **A mirror carries no local cwd, and no repo/branch at all** — herdr derives sidebar git state from the local workspace cwd, and there isn't one; the plugin's own README lists this as a limitation. So the palette shows the host in place of a path rather than the meaningless sentinel, and leaves `cwd` out of the search haystack for mirror rows (it is identical across all of them). Nothing in the palette filters, sorts or groups by repo — grouping is by host — so a repo-less row is never dropped.
- **Grouping reuses the navbar's rule** (`aliasFamilies`/`familyOf` in `src/web/src/lib/hosts.ts`), with mirror host keys living in the same namespace as ssh aliases: a mirror of a box lasso can also drive directly lands in that box's group instead of a parallel one beside it. lasso's own machine leads, the rest are alphabetical — herdr's creation order says nothing useful across nine hosts.
- **⌘K is scoped to the tab's host** (`PaneSwitcher`, off `useApp().host`), because with mirrors that host *is* the fleet. Also listing the other hosts' panes over ssh showed every mirrored pane **twice** — once as the local mirror, once as the remote pane it streams — and picking the remote copy moved the tab to another host (a terminal reload) to show what the mirror row already had on screen. The palette still requests `/api/all-panes` and narrows client-side: that aggregation's per-host success branch is the only scheduled thing that reconciles agent records (`fetchAllPanes` → `reconcileHostAgents`), so fetching one host instead would quietly stop tombstoning dead agents. `/api/agent-history` (closed sessions) is filtered by the same host key.
- **Closing a mirror locally does not close the remote** (`close_remote_on_local_close = false` on titan). Don't build UI that implies it does.
